# 产品需求文档（PRD）

## 1. 项目背景

旅行记账是一个移动端优先的旅行费用追踪应用，旨在帮助用户在多次旅行中管理费用，支持多币种记账和多人分账。随着出境游的普及，旅行者面临多币种消费、多人AA分账等复杂场景，传统记账工具无法满足需求。本产品针对这些痛点，提供一站式旅行财务管理方案。

## 2. 目标用户

| 用户类型 | 描述 |
|---------|------|
| 个人旅行者 | 需要记录多币种消费、管理旅行预算 |
| 团队出行组织者 | 需要管理多人共同消费、计算分账 |
| 频繁出差人员 | 需要按行程分类管理费用 |
| 背包客/自由行爱好者 | 需要轻量化、移动端友好的记账工具 |

## 5. 用户故事

### 账本管理
- 作为用户，我想创建一个旅行账本，以便按行程分类管理费用
- 作为用户，我想封存已结束的旅行账本，防止误操作修改历史数据
- 作为用户，我想为账本设置封面图，让账本列表更美观直观

### 记账
- 作为用户，我想快速记录一笔消费，包括金额、币种和分类
- 作为用户，我想用自然语言描述消费（如"午餐花了80"），让AI自动解析
- 作为用户，我想拍照上传小票，让AI自动识别消费信息
- 作为用户，我想记录共同消费并指定参与人，以便后续分账

### 分账
- 作为用户，我想查看每个人应付多少钱，以便旅行结束后结算
- 作为用户，我想标记某人已结清，方便追踪结算进度

### AI 旅行攻略
- 攻略功能已移除

### 密码重置
- 作为用户，我想通过邮箱直接重置密码，无需等待验证码

### 多币种
- 作为用户，我想设置当地货币汇率，让系统自动换算为本币金额
- 作为用户，我想查看不同币种的消费明细

## 6. 业务规则

| 规则 | 描述 |
|------|------|
| 封存只读 | 已封存账本不允许新增、编辑、删除交易和成员 |
| 均摊分账 | 共同账单在参与人之间平均分摊 |
| 双币存储 | 所有金额同时存储原币金额和本币金额 |
| 汇率联动 | 汇率变更触发该币种所有交易的本币金额重算 |
| 付款人包含 | 共同账单的付款人自动包含在参与人列表中 |
| 默认参与 | 共同账单未指定参与人时，默认所有成员参与 |
| 金额精度 | 金额使用 decimal(12,2) 存储，确保精度 |
| 人均预算 | 预算字段存储人均金额，详情页显示"我的预算"进度条，展示当前用户实际消费占比 |
| 成员编辑权限 | 账本所有成员（创建者和参与者）均可编辑账本信息和交易 |

## 7. 非功能需求

### 7.1 性能
- 页面首屏加载时间 < 2秒
- API 响应时间 < 500ms（常规操作）
- AI 解析响应时间 < 5秒

### 7.2 安全
- 密码 bcrypt 加密存储
- JWT Token 认证，支持过期机制
- SQL 参数化查询防注入
- 文件上传类型和大小限制（10MB）

### 7.3 兼容性
- 移动端浏览器优先（iOS Safari、Android Chrome）
- 响应式布局适配不同屏幕尺寸
- 支持微信内置浏览器

### 7.4 可用性
- 中文界面
- 移动端触控友好
- 操作反馈及时（Toast 提示）

### 7.5 可维护性
- 前后端分离架构
- RESTful API 设计
- 统一响应格式
- 模块化代码组织
